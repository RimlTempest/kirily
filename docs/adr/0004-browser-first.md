# ADR-0004: 画像をサーバーへ送らないことを既定にする

- 状態: 採用
- 日付: 2026-09-21

## 背景

背景透過にかける画像は、多くの場合その人の写真か、未公開の商品写真。
「アップロード不要」は機能ではなく、**この製品を選ぶ理由**になりうる。

一方、ブラウザで動くセグメンテーションモデルの精度には限界があり、
将来サーバー推論を足す可能性は捨てられない。

## 決定

1. 既定の経路では画像は一切ネットワークへ出ない。デコード・編集・
   エンコードはすべてブラウザ内で行う。
2. `apps/web/wrangler.jsonc` に R2 / KV / D1 のバインディングを置かない。
   置くということは、画像か、画像にまつわる何かをサーバーに持つということ。
   CI の `guard` が検査する。
3. リモート AI を足す場合、そのプロバイダは `info.requiresUpload: true` を
   宣言する。`selectAiBackend()` は `consent.allowsUpload` が真のときしか
   それを選ばない。同意 UI を通さずに真を渡さない。
4. ルートの `+layout.ts` は `ssr = false` / `prerender = true`。
   サーバーは静的ファイルを返すだけで、画像を見ない。
5. CSP で `connect-src 'self'` を指定し、依存が勝手に外へ出さないようにする。

## 結果

- トップページの「サーバーへは送信されません」が実装の性質になる
- 無料枠内で運用しやすい（Worker リクエストをほぼ消費しない）
- 巨大画像や高精度モデルはブラウザの制約を受ける
- この決定を変えるには ADR を書き、文言と同意 UI を同時に変える必要がある

## 代替案

- 既定でサーバー推論 → 精度は出しやすいが、選ばれる理由が消える
- R2 に一時保存 → 従量課金が止められず、TTL の運用も要る
