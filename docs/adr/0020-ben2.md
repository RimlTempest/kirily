# ADR-0020: BEN2 は現状 ORT Web で動かない

- 状態: 却下（再挑戦の条件つき）
- 日付: 2026-09-21

## なぜ試したか

ADR-0010 の評価セットが、いまの上限を数字で示していた。

- `ring-with-hole` は IoU 0.805。**両方の段が本物の穴を完全に埋める**
- `thin-strands` の Boundary F は色差マッティングで 0.990〜0.992 まで来たが、
  細い房そのものはモデルの解像度に縛られている

BEN2 の形はこの 2 つに効きそうだった。ベースの後に
**ベースが自信を持てなかった画素だけを再処理する refiner** が付く構造で、
髪が居るのはまさにそこである。MIT、ONNX 公開済み、HuggingFace で 72k ダウンロード。

`kirily-design.md §37` の「切り抜き品質」に対する、次の一手の候補だった。

## 測って分かったこと

実際に積んで動かした。213 MiB（9 shard）を取得し、
`onnx_run.py` から前処理を確定させた（`ToTensor()` のみ、
つまり 0..1 で ImageNet 統計を使わない。他の 3 つと違う）。

### WebGPU：セッションが作れない

```
Exception during initialization: transformer_memcpy.cc:254
IsNodeCompatibleWithProvider(const Node &) !node_provider_type.empty() was false.
Provider type for Pow node with name '/dec_blk3/norm1/Pow' is not set.
```

デコーダの LayerNorm にある `Pow` ノードに、**どの実行プロバイダも
割り当てられない**。しかもこれは **213 MiB を落とし終えたあとに起きる。**
ADR-0007 がまさに防ごうとした失敗の形である。

### WASM：セッションは作れるが推論で落ちる

```
AI_INFERENCE_FAILED failed to call OrtRun(). ERROR_CODE: 6, std::bad_alloc
```

`plan.ts` のコメントが予告していたとおり、1024² のモデルは
32bit の wasm ヒープに収まらない。

**この結果はモデル自体が壊れていないことの証拠でもある。** CPU の EP は
この `Pow` を受け取れる。落ちているのは WebGPU 側の op 対応である。

### 試して効かなかったもの

| 試したこと                                    | 結果                                       |
| --------------------------------------------- | ------------------------------------------ |
| `graphOptimizationLevel: 'all'`               | **既に設定済み**。LayerNorm は融合されない |
| `executionProviders: ['webgpu', 'wasm']`      | 同じエラー。分割時はどちらも取らない       |
| 他の配布元（`not-lain/BEN2`、`1038lab/BEN2`） | ONNX を公開していない                      |
| fp16 版                                       | **どこにも存在しない**                     |

## 決定

**積まない。**

動かすには `Pow(x, 2)` を `Mul(x, x)` に置き換えるグラフ改変が要る。
それは、

1. 第三者のモデルを**改変したもの**を配ることになり、
2. `models:fetch` に ONNX を書き換える工程が増える。
   ADR-0014 で「変換を挟むとビルドに Python と onnx への依存が増える」として
   断った依存が、そのまま戻ってくる。

得られるものは**まだ測れていない**品質の向上である。
213 MiB と保守し続けるグラフ改変を、測っていない利益と引き換えにはしない。

## 再挑戦の条件

どれか 1 つで十分:

- ORT Web の WebGPU EP がこの `Pow` を扱えるようになる
- 誰かが ONNX を再エクスポートして公開する（fp16 だとなお良い）
- Kirily 側にグラフ改変の必要がほかにも出てきて、
  その工程を持つ理由が BEN2 以外にもできる

再挑戦したときに測るべきは `ring-with-hole` の IoU（現状 0.805）と
`thin-strands` の Boundary F（現状 0.990〜0.992）である。

## 却下した他のモデル

| モデル                | ライセンス          | 判断                                                         |
| --------------------- | ------------------- | ------------------------------------------------------------ |
| RMBG-2.0              | **other（非商用）** | ADR-0007 でライセンスを第一条件にした判断と矛盾する          |
| BiRefNet（フル）      | MIT                 | fp16 でも 467 MiB                                            |
| BiRefNet-matting / HR | MIT                 | **ONNX が無い。** 髪に強いとの報告があり、誰かが出せば最有力 |
