# ADR-0019: バケツに輪郭と AI を与える

- 状態: 採用
- 日付: 2026-09-21

## 背景

`pale-subject-on-white.png` の隅をバケツでクリックして、選択範囲を測った。

```
完全に選択  597,306 px
部分的      2,060 px   ← 全体の 0.3%
```

輪郭を横切った断面（row 1100、画像側は 254→249→230→198→156→124 と滑らかに落ちる）:

```
画像の R : 254 249 230 198 156 124
選択     : 255   0 255   0   0   0
```

**1 画素の飛び石がある。** flood fill は画素ごとに到達可能かを判定するので、
その前線は階段状になる。塗った内側は滑らかでも、**縁は必ず硬い**。

これが利用者の言う「ジャギー」である。

## 決定 1：選択範囲もマスクである

マスクの縁は、閾値が落ちた場所ではなく**画像から決める**。
これは既にこのリポジトリの方針で、AI のマスクがそうしている。
同じ 2 段をバケツの選択にも通す。

1. guided filter が境界を実際のエッジへ寄せる（ADR-0008）
2. 合成の式が画素からアルファを決める（ADR-0013）

新しいアルゴリズムは 1 つも要らない。選択を反転してから通すだけで、
どちらも「マスク＝前景」として読むのに対し、バケツが取るのは普通は背景だからである。

### 結果

```
部分的   2,060 px (0.3%)  →  25,791 px (4.2%)
```

断面（row 1100）:

```
画像の R : 254 249 230 198 156 124
前       : 255   0 255   0   0   0
後       : 255 253 215 149  63   0
```

**画像がランプならランプになり、画像が鋭ければ鋭いまま**になる。
row 564 は画像自体が 2 画素で 253→115 と落ちるので、
そこでは中間値が 1 つしか出ない。それが正しい。

### 何もしない場合は何もしない

選択が空、あるいは全面のときは早く返す。境界が無いので
寄せる先も無く、平坦なマスクにフィルタを掛けても誤差しか足せない。

## 決定 2：AI の輪郭で止める

バケツは色しか見ていなかった。白い襟と白い背景は OKLab で 0.0187 しか離れておらず、
背景自身のばらつき 0.0030 と比べれば離れてはいるが、
**役に立つ広さの許容差なら必ず中に入る**（ADR-0012 で計測）。

AI のマスクはそれを知っている。だから聞く。

クリックが落ちた側（`alpha >= 128` か否か）を覚え、
反対側の画素は**色がどれだけ近くても到達不能**にする。

ガイドに使うのは **AI の層（`base`）だけ**で、合成後のマスクではない。
合成後には利用者の修正が入っているので、
自分の過去の塗りに導かれることになる。

### 測った結果

許容差 0.08（緩い側）で隅から塗ったとき:

|            | 角（背景） | 顔の中心 | 髪  |
| ---------- | ---------- | -------- | --- |
| ガードあり | 0          | **255**  | 255 |
| ガードなし | 0          | **4**    | 255 |

ガードが無いと**顔が丸ごと食われる**。あると残る。

### 切れるようにした

**マスクそのものを直したいときに、マスクに導かれては困る。**
AI が襟を取り落としているときにバケツで拾いに行く、というのが
この道具の一番の仕事なので、そこで AI が邪魔をしてはならない。

チェックボックスは**マスクがあるときだけ**出す。
何もできないスイッチは、無いより悪い。

## 費用

1254²、warm:

```
flood          70ms
invert          8ms
refineMask     21ms
field bg       12ms
field fg       28ms
colourMatte     9ms
合計          148ms
```

初回は JIT の分だけ増えて約 240ms。クリックは意図的な操作なので許容する。
縮めるなら、まず `estimateField`（40ms）を flood の bounds に絞ることになる。

## 途中で見つけたバグ

このテストを書いている最中に、`refineMask` が**一様なマスクを変えてしまう**
ことに気づいた。1×64 の帯で 255 が 161 まで落ちる。

原因は `boxBlur` の端の詰め物で、辺が窓より短いとき足りていなかった
（半径 1・高さ 1 なら 3 画素分の窓に 2 画素しか入らず、値が 2/3 になる）。
**Rust 版もまったく同じ間違いをしていた** — 規約どおり両者は一致していた。

実画像には届かない（1254² なら統計の格子は 314²、半径 1）。
実際、評価セットの **40 指標は 1 つも動かなかった**。
それでも平坦なマスクを変えるフィルタはどの大きさでも間違いなので、
両方直して両方にテストを置いた。
