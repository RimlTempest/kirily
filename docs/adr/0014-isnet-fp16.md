# ADR-0014: IS-Net を fp16 にする

- 状態: 採用
- 日付: 2026-09-21

## 背景

IS-Net general-use は 170 MiB。3 段のうち最も重く、
**この段を使う端末は BiRefNet が動かない端末**（ADR-0007）なので、
高精度な切り抜きを得るための実質的な代価がこの 170 MiB だった。

BiRefNet は既に fp16 で配信している。IS-Net だけ fp32 なのは、
変換済みの配布物を探していなかったからである。

この段は `plan.ts` により **WebGPU でしか走らない**。
半精度がネイティブに動く場所なので、fp32 を配る理由が無い。

## 決定

**`imgly/isnet-general-onnx` の `model_fp16.onnx` に差し替える。**
84.1 MiB（88,152,708 バイト）。

### 候補の選定

| 配布元                      | ライセンス   | 判断                                                       |
| --------------------------- | ------------ | ---------------------------------------------------------- |
| `onnx-community/ISNet-ONNX` | **AGPL-3.0** | 却下。本プロジェクトは Apache-2.0 / MIT の重みで揃えている |
| `imgly/isnet-general-onnx`  | MIT          | 採用                                                       |

元の重みは xuebinqin/DIS（Apache-2.0）で、MIT の再配布はそれと矛盾しない。

### URL をコミットで固定した

`imgly` の fp32（176,149,806 B）は rembg 版（178,648,008 B）と**別物**で、
再エクスポートである。前処理がグラフに焼き込まれていれば、
`ModelSpec` の正規化が二重に掛かって「それらしいが間違ったマスク」が出る。
落ちないので、測るしかない（`kirily-image-pipeline` の規約）。

あわせて BiRefNet の URL も `resolve/main` からコミット指定に変えた。
ADR-0009 が「GitHub Actions はタグでなく commit SHA で固定する」と
書いている理由がそのまま当てはまる。**`resolve/main` は可動参照である。**

HF が返す `x-linked-etag` が SHA-256 と一致することを確認したうえで、
これまでどおりサイズと SHA-256 でも検証している。

## 測った結果

ADR-0010 の評価セット、WebGPU 段。

| ケース            | IoU         | Boundary F  | MAE         | halo        |
| ----------------- | ----------- | ----------- | ----------- | ----------- |
| solid-disc        | 1.000→1.000 | 1.000→1.000 | 0.000→0.000 | 0.004→0.004 |
| low-contrast      | 0.999→0.999 | 1.000→1.000 | 0.009→0.009 | 0.008→0.008 |
| thin-strands      | 0.997→0.997 | 0.990→0.990 | 0.001→0.001 | 0.096→0.096 |
| ring-with-hole    | 0.804→0.804 | 0.818→0.818 | 0.071→0.071 | 0.075→0.075 |
| gradient-backdrop | 1.000→1.000 | 1.000→1.000 | 0.000→0.000 | 0.009→0.009 |

**20 個の数字が 1 つも動いていない。** 正規化が二重に掛かっていない証拠でもある。

実画像（`pale-subject-on-white.png`、1254²）での書き出しマスクの差:

```
平均差    0.004 / 255
8 を超える画素  193 / 1,572,516  (0.012%)
```

速度は **9133ms → 7497ms**（18% 短縮）。ダウンロードが半分になり、
GPU 上の半精度演算も速い。

配信する静的アセットは **284 MiB → 198 MiB**。

## 却下した案

**自前で fp32 から変換する。** `convert_float_to_float16` は Python の
onnxruntime にあるが、`models:fetch` は URL から再現できることが前提で、
変換を挟むとビルドに Python と onnx への依存が増える。
ADR-0009 の「`postinstall` を要求する依存は調べてから」と同じ理由で、
既存の配布物を固定するほうが攻撃面が小さい。

**AGPL の配布物を使う。** サイズは同じだが、ADR-0007 で
ライセンスを選定の第一条件にした判断と矛盾する。
