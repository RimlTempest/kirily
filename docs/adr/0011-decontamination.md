# ADR-0011: ソフトエッジから背景色を抜く

- 状態: 採用
- 日付: 2026-09-21

## 背景

半分だけ覆われた画素は `subject·a + background·(1-a)` を持っている。
アルファを付けただけで書き出すと、その混色がそのまま残る。

エディタの背景は市松模様なので、これは**画面上ではほぼ見えない**。
書き出したファイルを別の背景に置いた瞬間に出る。見つかるタイミングとして
最悪である。

ADR-0010 の評価セットで測った、手を入れる前の値（soft 画素の平均チャンネル誤差）:

| ケース            | 除染前 |
| ----------------- | ------ |
| thin-strands      | 0.382  |
| solid-disc        | 0.277  |
| ring-with-hole    | 0.235  |
| gradient-backdrop | 0.235  |
| low-contrast      | 0.016  |

`low-contrast` だけ小さいのは、被写体と背景がほぼ同じ色で
混ざるものが無いからで、実装が良いからではない。

## 決定

**背景色を粗いグリッドで推定し、画素ごとに混色を解く。**

```
subject = (observed - background·(1-a)) / a
```

### 背景は 1 色ではない

`decontaminate_edges` は Rust 側に「背景色を 1 つ受け取る」形で
実装されていた。これはスタジオの背景紙では動き、それ以外では
画像全体に間違った色を塗る。

代わりに `BackgroundField` を持つ。32px 角ごとに 1 色、
バイリニアで参照する。1254² で 18KB。全解像度のバッファをもう 1 枚
持つ代わりであり、グラデーションがグラデーションのまま出る。

被写体の内側に埋もれて背景を 1 画素も見なかったセルは、
**背景を見たセルから幅優先で borrow する**。黒のまま残すと、
そのセルに接する輪郭に黒い縁を塗ることになる。

### いつ測るか

**AI が走ったときに 1 回だけ。** 背景は写真の性質で、
ユーザーが塗っている間に変わらない。ひと筆ごとに全画素を走査するのは
エディタで最も重い処理になる。

AI を走らせていない場合は `null`、つまり除染しない。手描きのマスクだけでは
「被写体の後ろに何があったか」を言う根拠が無い。

### どこで適用するか

プレビューと書き出しの**両方**。片方だけだと、見えているものと
保存されるものが違う（kirily-design.md §16 の Preview / Export 分離は
「別の経路」であって「別の結果」ではない）。

- `renderViewport` … サンプルした画素をその場で補正する
- `exportImage` … アルファを入れた後、JPEG の合成より前

### Rust 版を消した

`kirily_raster::decontaminate_edges` を削除した。ルール上
`kirily-raster` と `image-core` は同じ振る舞いを持つが、
**違うアルゴリズムの 2 実装は、実装が無いことより悪い。**

背景の推定はレンダラも必要とし、レンダラは WASM エンジンを持たない。
Rust に置くと、難しい方の半分が書き出し側からしか届かない 2 つ目の実装になる。

計測（1254²、soft 画素 0.52%）:

```
estimateBackground  20.1 ms   ← AI 実行ごとに 1 回
decontaminate        4.3 ms   ← 書き出し時、全解像度
```

推論の数秒に対して無視できる。`solidifyInterior` と同じ判断である。

## 測り直した結果

| ケース            | 除染前 | 除染後 | 差         |
| ----------------- | ------ | ------ | ---------- |
| thin-strands      | 0.382  | 0.135  | **−0.247** |
| solid-disc        | 0.277  | 0.075  | −0.202     |
| gradient-backdrop | 0.235  | 0.085  | −0.150     |
| ring-with-hole    | 0.235  | 0.122  | −0.113     |
| low-contrast      | 0.016  | 0.008  | −0.008     |

IoU / Boundary F / MAE は**小数第 3 位まで 1 つも動いていない**。
色だけを触ったという主張が、そのまま数字になっている。

## 残った縁は除染では直らない

`pale-subject-on-white.png` を濃紺の上に置くと、まだ淡い縁が見える。
輪郭を横切って測った:

```
x=88  a=1   rgb=255,255,255
x=94  a=13  rgb=255,255,255
x=100 a=44  rgb=255,255,255
x=106 a=244 rgb=112,155,204
```

色は純白、つまり**画素は完全に背景**である。それでもマスクが
「5〜17% 覆われている」と言っている。混色を解く式はこの画素について
正しく答えている（背景しか無いのだから背景色が返る）。

`refineMask` を外して測っても同じ帯が出る（x=94 の 1 から
x=104 の 240 まで 10px）。つまり guided filter のせいではなく、
**320² のマスクを 1254² へ引き伸ばしたときのランプ**である。

これは色の問題ではなくアルファの問題で、ADR-0010 の
`boundaryFScore` と `mae` が測っている対象そのもの。
直す手段は解像度の高いモデルかマッティング段であって、除染ではない。

## 却下した案

**低いアルファを 0 に切り捨てて帯を消す。** 細い髪はまさに
低いアルファでできている。Kirily が守ろうとしているものを、
症状を隠すために捨てることになる。

**画素ごとに近傍の背景画素を平均する。** グリッドより正確だが、
輪郭画素 × 半径² のコストがかかり、結果はグリッドをバイリニアで
読んだものとほぼ変わらない（背景はそもそも滑らかである）。
