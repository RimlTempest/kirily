# ADR-0013: 輪郭を画素から決める（色差マッティング）

- 状態: 採用
- 日付: 2026-09-21

## 背景

セグメンテーションのマスクは「モデルの解像度における、モデルの輪郭」である。
画像の解像度へ引き伸ばすと、輪郭はランプになる。

ADR-0011 で `pale-subject-on-white.png` の輪郭を横切って測った:

```
x=88  a=1   rgb=255,255,255
x=94  a=13  rgb=255,255,255
x=100 a=44  rgb=255,255,255
x=106 a=244 rgb=112,155,204
```

**色は純白、つまり完全に背景**なのに、マスクは「5〜17% 覆われている」と
言っている。市松模様の上では見えず、濃い背景に置くと被写体全体を囲む
グローになる。

`refineMask`（guided filter）を外しても同じ帯が出るので、
これはフィルタのせいではなくモデル解像度の問題である。

## 決定

**合成の式を解いて、α を画素から直接求める。**

```
I = a·F + (1-a)·B
```

F と B を局所的に一定とみなすと、a は観測色を F–B の直線へ射影した値になる:

```
a = dot(I - B, F - B) / |F - B|²
```

**B は ADR-0011 で既に測っている。** F は同じ推定器がマスクの反対側を
見るだけなので、実装は `ColourField` の一般化で済む。

### 一般化した `ColourField`

`estimateBackground` を `estimateField(rgba, size, mask, options)` にした。
`options.side` が背景と前景を切り替える。同じことを 2 か所に書かないため。

セルの大きさは別にした。

|      | セル    | 理由                                                                                     |
| ---- | ------- | ---------------------------------------------------------------------------------------- |
| 背景 | 32px    | 写真の背景はゆっくり変わる。1254² で 18KB                                                |
| 前景 | **8px** | 被写体の縁は違う。髪・肌・襟が数画素で隣り合うので、平均すると画像のどこにも無い色になる |

### 触る範囲

**帯だけ。** モデルが 0 または 255 と言った画素には手を出さない。
これは輪郭の補正であって、再セグメンテーションではない。

### F と B が同じ色のときは何もしない

白いシャツと白い背景では、式に割るものが無い。
**確信を持った間違いは、モデルの曖昧さより悪い。**

閾値は測って決めた。`pale-subject-on-white.png` の帯で |F−B| は
中央値 173（sRGB 距離）、24 を下回るのは **0.8%** だけ。
その 0.8% がまさに白 × 白なので、そこはモデルに任せる。

### 順番

`refineMask` の**後**、全解像度で走らせる。guided filter は
モデルの輪郭を画像の輪郭へ寄せ、こちらは画像の画素から輪郭を決める。
先に走らせると、フィルタがせっかく立てた縁をまた鈍らせる。

## 結果

`bun run --filter @kirily/e2e baselines` で測り直した。

### CPU 段（U²-Netp, 320²）

| ケース            | IoU         | Boundary F      | MAE         | halo            |
| ----------------- | ----------- | --------------- | ----------- | --------------- |
| solid-disc        | 0.999→1.000 | 1.000→1.000     | 0.002→0.000 | 0.075→**0.005** |
| low-contrast      | 0.998→0.998 | 1.000→1.000     | 0.011→0.011 | 0.008→0.008     |
| thin-strands      | 0.995→0.997 | **0.961→0.992** | 0.003→0.000 | 0.135→**0.044** |
| ring-with-hole    | 0.805→0.808 | **0.818→0.883** | 0.073→0.069 | 0.122→**0.068** |
| gradient-backdrop | 0.999→1.000 | 1.000→1.000     | 0.002→0.000 | 0.085→**0.009** |

### GPU 段（IS-Net, 1024²）

| ケース            | Boundary F      | halo        |
| ----------------- | --------------- | ----------- |
| thin-strands      | 0.993→**0.990** | 0.149→0.096 |
| ring-with-hole    | 0.818→0.818     | 0.111→0.075 |
| solid-disc        | 1.000→1.000     | 0.060→0.004 |
| gradient-backdrop | 1.000→1.000     | 0.060→0.009 |

**いちばん大きい結果: CPU 段の輪郭が GPU 段に並んだ。**
細い房の Boundary F が 0.961 → 0.992 で、GPU 段の 0.990 と同じ水準。
輪郭の鋭さを決めているのがモデルの解像度ではなくなった、ということ。
WebGPU の無い端末でも同じ輪郭が出る。

`pale-subject-on-white.png` の半透明画素は
**CPU 段で 232,243 → 107,662、GPU 段で 85,131 → 40,640**。どちらも半減した。

### 悪くなったもの

GPU 段の細い房 Boundary F が 0.993 → 0.990。−0.003 で
ラチェットの余裕（0.02）の中だが、実際に下がっている。
1024² のマスクは既に十分鋭く、そこに射影を当てると
局所推定の誤差のぶんだけ荒れる。CPU 段の +0.031 と引き換えである。

CPU 段の出力には輪郭にわずかな斑が残る。U²-Netp の帯が広く、
F の推定を外す画素がそのぶん多いため。グロー全体と引き換えなので採った。

## 費用

1254²、全解像度:

```
estimateField(背景, セル 32)   7.5 ms
estimateField(前景, セル 8)    9.9 ms
colourMatte                   11.1 ms
合計                          28.5 ms
```

推論の数秒に対して無視できる。ADR-0011 と同じ理由で TypeScript のみ。

## 却下した案

**閾値で二値化する。** 白いシャツは取れるが、
ADR-0008 が守っている柔らかい髪の輪郭を潰す。
α を連続値で出すことが要点である。

**F を最近傍の確信画素から取る（sampling-based matting）。**
グリッドより正確だが、全解像度の色バッファ 2 枚（4K で 48MB）か
同等の索引が要る。グリッドで測った結果が十分だったので、
`kirily-image-pipeline` の「計測してから速くする」に従って採らない。

**ViTMatte などのマッティング段を積む。** 2 段目のモデルは
ダウンロードと推論時間を倍にする。まず式を解いて、
それで届かないところが分かってから考える。
