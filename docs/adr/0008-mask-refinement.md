# ADR-0008: マスクの輪郭を元画像に合わせる

- 状態: 採用
- 日付: 2026-09-21

## 背景

モデルは 1024² で動き、マスクはユーザーの画像サイズへ拡大される。
どれだけ丁寧に拡大しても、出てくる輪郭は**モデルの解像度でのモデルの輪郭**で、
被写体の実際の境界の近くにあるだけで、その上には乗っていない。
4000px の画像なら 3.9 倍に伸ばすので、ずれも階段も目に見える。

## 決定

### 1. 前処理は「引き伸ばし」のまま（測定で確認）

推論入力を正方形へ引き伸ばすのは一見雑だが、正しい。
DIS / BiRefNet は正方形にリサイズした画像で学習されており、
比を保ってパディングすると 1024² の一部を余白に使うぶん被写体の画素が減る。

フィクスチャに白帯を足して比を変え、正方形のまま推論した結果を正解として測った:

| 比    | 引き伸ばし    | レターボックス |
| ----- | ------------- | -------------- |
| 1.5:1 | IoU **0.978** | IoU 0.795      |
| 2:1   | IoU 0.903     | IoU **0.917**  |

通常の比では引き伸ばしが明確に勝つ。極端な比では逆転するが、
そこは本来タイル推論か動的解像度モデルの領分。

### 2. 推論はプレビューではなく元画像から行う

以前はプレビュー（画面用に縮小済み）をモデルへ渡していた。
元画像 → プレビュー → 1024² → プレビュー → 元画像 と 4 回リサンプルしており、
モデルが見る前に detail が落ちていた。いまは元画像 → 1024² → 元画像 の 2 回。

あわせてリサンプラを書き直した。**縮小時にフィルタの支持幅を比率で広げる。**
素朴な bilinear は縮小率に関わらず 2×2 しか読まないので、4000px を 1024px に
するとき画素の 4 分の 3 を捨ててエイリアスする。支持幅を広げれば同じコードが
面積平均になる。

### 3. マスクの拡大は Lanczos

bilinear は対角の輪郭を折れ線として再構成する。これが拡大後に階段として見える。
測定: 32² の対角エッジを 128² へ拡大したとき、50% 等値線の
ぶれ（RMS）は triangle 0.256px、lanczos3 0.175px。

プレビュー用のマスク縮小は bilinear のまま。こちらは編集のたびに走るので、
1 回きりの AI 経路とはコストの意味が違う。

### 4. Guided filter で輪郭を元画像に吸い付ける

He・Sun・Tang (2010) の guided filter を、**元画像をガイドに**マスクへ 1 回かける。
出力がガイドの局所線形関数になるので、ガイドにエッジがあればマスクがそこへ寄る。
論文が "guided feathering" と呼んでいる応用そのもの。

高速版 (He & Sun, 2015) を使う。統計量を 1/s に間引いて計算するので
O(n/s²) で済み、見た目の差はない。box filter だけで書けるので
`crates/kirily-raster/src/guided.rs`（Rust）と
`packages/image-core/src/guided.ts`（TypeScript フォールバック）に置いた。

#### ガードレールが本体より重要

**素のまま当てると再セグメンテーションを始める。** 実測で踏んだ:
髪の中の白いハイライト（`#fefefe`）が、背景（`#fbfbfa`）と同じ明るさのため
「明るい＝背景」と判断されて消えた。フィクスチャが選ばれた理由そのもの。

二重に縛る。

1. **届く範囲を輪郭補正に必要なぶんに限る。**
   半径は長辺の 0.5%（`refineRadiusFor`）。1254px で 6px、4000px で 20px。
   これならモデルの輪郭と実際の輪郭の差は埋められるが、
   輪郭から被写体の内部までは届かない。
2. **マスクが既に迷っている場所にしか当てない。**
   マスクの局所分散が `minVariance`（alpha の 2%、約 5 階調）未満なら
   元の値を保つ。モデルが平坦に不透明と言った領域について、
   ガイドは「被写体が何か」の証拠にならない。

どちらも回帰テストがある（`keeps_a_confident_region_even_when_the_guide_disagrees`）。

ガイドは輝度で、色ではない。色版は窓ごとに 3×3 の逆行列が要り、
色相だけが違うエッジを分離できるが約 10 倍のコスト。計測してから。

## 結果

フィクスチャ（1254²、背景と肌がほぼ同じ明度）での実測:

|                 | 輪郭のぶれ（前） | 輪郭のぶれ（後） | 所要        |
| --------------- | ---------------- | ---------------- | ----------- |
| U²-Netp (CPU)   | 0.304 px         | 0.301 px         | 2.2s → 2.3s |
| IS-Net (WebGPU) | 0.276 px         | **0.224 px**     | 6.4s → 6.5s |

高精度段で 19% 改善。軽量段はほぼ変わらない — 320² を 4 倍に拡大した
マスクには吸い付く先の情報が残っていないため。これは想定どおりで、
精緻化は品質段にこそ効く。

目視では、以前ギザギザだった髪の中のハイライトの縁が滑らかになり、
アホ毛の内側の抜けが締まった。

## 代替案

- **全体に feather をかける** — 階段は消えるが輪郭全体が甘くなる
- **closed-form matting (pymatting)** — 品質は上だが巨大疎行列を解くので
  1254² でもブラウザには重い
- **trimap + ViTMatte の 2 段** — 最高品質だがモデルがもう 1 本増える
- **色ガイドの guided filter** — 約 10 倍のコスト。必要になったら
