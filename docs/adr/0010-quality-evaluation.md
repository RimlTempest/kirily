# ADR-0010: 切り抜き品質を数値で測る

- 状態: 採用
- 日付: 2026-09-21

## 背景

ここまでの品質の根拠は、E2E の中の点検査だった。

```ts
expect(alpha['faceCentre']).toBeGreaterThan(223)
```

これは「マスクが崩壊した」ことは捕まえる。捕まえないものが 2 つある。

1. **交換**。肩が綺麗になり髪が荒れた変更は、どちらの点も踏まなければ
   通ってしまう。
2. **改善**。「マッティングを入れると髪が良くなる」を確かめる手段がない。
   ADR-0008 で letterbox を却下したときは IoU を手で測ったが、
   その測り方はコードに残っていない。

実写には正解マスクが無い。誰かが輪郭をなぞったものは、その人の意見である。

## 決定

**正解のアルファが算術的に分かる画像を合成し、3 つの指標で測る。**

### データセット（`tests/fixtures/cases.ts`）

被写体と背景を決めて `observed = subject·a + background·(1-a)` で合成する。
`a` は 4×4 のスーパーサンプリングで求めた被覆率そのもの。
なぞったマスクではないので、「モデルが髪で 3 点悪い」が
輪郭を描いた人の話ではなくモデルの話になる。

5 枚。**1 枚ごとに「何を落とすための画像か」を書く**（`Case.catches`）。

| ケース              | 落とすもの                                           |
| ------------------- | ---------------------------------------------------- |
| `solid-disc`        | 最も簡単な入力でシルエットが崩れること               |
| `low-contrast`      | 背景よりわずかに明るいだけの被写体を見失うこと       |
| `thin-strands`      | 細部が落ちること（マッティングが取り戻す対象）       |
| `ring-with-hole`    | 本物の穴が、半透明の内部を閉じる処理に埋められること |
| `gradient-backdrop` | 背景が単色でなかったときに縁が残ること               |

### 指標（`packages/image-core/src/metrics.ts`）

| 指標                | 見るもの                                  | 見ないもの                               |
| ------------------- | ----------------------------------------- | ---------------------------------------- |
| `iou`               | シルエット                                | ソフトエッジ（構造上、原理的に見えない） |
| `boundaryFScore`    | 輪郭。DAVIS と同じく対角の 0.75% の許容差 | 面                                       |
| `meanAbsoluteError` | アルファそのもの                          | —                                        |

3 つとも要る。**硬く抜いたソフトエッジは IoU では満点になる。**
`metrics.test.ts` にその 1 件がある。

### ラチェット（`tests/e2e/specs/quality.spec.ts`）

`baselines.json` に記録し、**0.02 より下がったら落とす**。
上がったら書き戻す（`bun run --filter @kirily/e2e baselines`）。

基準値は **Playwright の project ごと**に持つ。project が段を決めるからで、
`desktop` は GPU アダプタが無いので U²-Netp、`desktop-webgpu` は
その端末の上限が許す段になる。2 つを並べることが、
段についての主張を確かめる方法そのものになる。

## 最初に測って分かったこと

| ケース            | IoU (CPU / GPU)   | Boundary F (CPU / GPU) |
| ----------------- | ----------------- | ---------------------- |
| solid-disc        | 0.999 / 0.999     | 1.000 / 1.000          |
| low-contrast      | 0.998 / 0.999     | 1.000 / 1.000          |
| thin-strands      | 0.995 / 0.996     | **0.961 / 0.993**      |
| ring-with-hole    | **0.805 / 0.805** | 0.818 / 0.818          |
| gradient-backdrop | 0.999 / 0.999     | 1.000 / 1.000          |

**1. 高精度段が実際に効いているのは輪郭だった。**
`thin-strands` の Boundary F が 0.961 → 0.993。IoU はほぼ動かない
（細い房は面積の 1.4% しかない）。段を増やした価値が、
初めて面ではなく輪郭の数字として出た。

**2. 両方の段が穴を完全に埋める。**
0.805 は円環の面積 ÷ 円盤の面積（π(0.34²−0.15²) / π·0.34² = 0.805）に
小数第 3 位まで一致する。つまり穴が部分的に残っているのではなく、
**全部埋まっている**。

犯人を `solidifyInterior` だと推測したが、**測ったら違った**。
IS-Net 段の `solidifyInterior` を切って測り直しても
0.805 / 0.818 / mae 0.071（有効時 0.072）で変わらない。
U²-Netp は元から無効。つまり**モデル自身が円環を塊として返している**。

U²-Netp は saliency（顕著性）モデルなので納得できる。IS-Net は
dichotomous segmentation なので意外だが、数字がそう言っている。

これは実装の欠陥ではなく、いま積んでいるモデルの性質である。
マグカップの取っ手や腕と胴の隙間は、現状**抜けない**。
`kirily-design.md §37` の「切り抜き品質」に対する既知の限界として、
ここに記録する。改善の候補は confidence map かマッティング段で、
効いたかどうかはこの表の `ring-with-hole` の行が答える。

## 却下した案

**実写に正解マスクを手で描く。** 1254² の髪の輪郭を画素単位で正しく
描くことはできない。描いたものを正解と呼ぶと、モデルの誤差ではなく
描き手の誤差を測ることになる。合成なら被覆率が定義そのものになる。

**単一の指標にまとめる。** 3 つの数字が別々に動くことに意味がある。
1 つにすると、輪郭が良くなって面が悪くなった変更が「横ばい」に見える。

**Rust 版の指標。** 製品の経路から誰も呼ばない。二重実装は
自分のテストしか動かさないコードになる。
