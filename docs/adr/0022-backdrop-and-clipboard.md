# ADR-0022: 背後に敷くものと、クリップボード

- 状態: 採用
- 日付: 2026-09-21

## 背景

背景を消すことは目的ではない。切り抜きは**何かの上に置かれる**。

Kirily は色を敷けたが、JPEG のときだけで、しかも
**JPEG に選択肢が無いから**だった。意図して選べるものではなかった。

もう 1 つ。ブラウザだけで完結する道具が、

- スクリーンショットをクリップボードから直接開けない
- 結果を次のアプリへ渡すのにダウンロードフォルダを経由させる

のは、**ブラウザが一番得意な部分を利用者にやらせている**。

## 決定 1：背後に敷くもの

`なし` / `色` / `画像` の 3 つ。どの形式でも選べる。

### JPEG に「なし」は出さない

灰色にするのではなく**消す**。透明を保てない形式は拒否しているのではなく、
そもそもそういう概念が無いからである。

`effectiveBackdrop()` が 1 か所でそれを決める。
3 か所で判断すると、プレビューと書き出しが食い違う。

### 枠取りは画像全体に対する cover

CSS の `cover` と同じ規則 — 枠を埋め、比を保ち、はみ出しは切る。

**crop ではなく画像全体に合わせる。** crop に合わせると、
トリミングを動かすたびに背景が被写体の下で滑る。

純粋関数（`coverTransform`）にしてあるので、
プレビューと書き出しが互いに問い合わせずに同じ枠取りを出せる。

### プレビューは CSS で敷く

ここだけ「同じ経路」から外れている。背景はキャンバスの後ろの要素に
`background-size: cover` で描き、書き出しは `compositeBackdrop` が
元解像度で合成する。

枠取りは同じ式なので**見える枠は一致する**。違うのはブラウザの縮小
フィルタと Kirily の合成で、**背景はそれが問題にならない唯一の層**である。
被写体でこれをやれば ADR-0016 が全画素で検証している性質が崩れるが、
背後に敷く写真の補間の差は、利用者が判断できるものを何も変えない。

レンダラに 4 枚目のテクスチャを足す変更を回避できるのが対価である。

## 決定 2：クリップボード

**貼り付け**は `document` の `paste` を聴く。スクリーンショットを撮って
Cmd+V、が実際の使われ方で、`paste` イベントはファイルを直接運んでくるので
**権限を聞かずに済む**。

**コピー**は `ClipboardItem` で書き出す。`canCopy()` が偽なら
ボタンを出さない。

`imageFrom()` は DOM の `DataTransferItem` ではなく
**必要な形だけ**を受け取る。テストが素のオブジェクトを渡せるようになり、
関数が何を読むのかが署名に出る。

`writeImage` は解決済みの Blob ではなく **Blob を作る約束**を
`ClipboardItem` に渡す。Safari は await を挟むとユーザー操作との
結び付きを失い、結び付いていない書き込みは拒否される。

## 一緒に直したこと

`download` と `copy` が同じ `render()` を使う。違いは blob の行き先だけで、
共有していないと**片方だけ違う絵になる**余地が残る。

`readPixels` の戻り値を `Uint8ClampedArray<ArrayBuffer>` に狭めた。
キャンバスが共有バッファを返すことは無く、そう書いてあることが、
この画素を `ImageData` に渡すときにアサーションを要らなくする。

## テスト

`backdrop.spec.ts` が**書き出したファイルの角**を読む。
プレビューにしか存在しない背景は、Preview / Export を分けた意味が
失われている状態そのものなので。

- なし … アルファ < 32
- 色 … PNG（アルファを保てる形式）でもアルファ 255、角が黒
- 画像 … アルファ 255、角が青
- JPEG … 「なし」が消えている

## 却下した案

**レンダラに背景テクスチャを足す。** 厳密には正しいが、
WebGL と TypeScript の両方に 4 枚目を通す変更になる。
背景は補間の差が見えない層なので、対価に見合わない。

**crop に合わせて敷く。** トリミングのたびに背景が滑る。
