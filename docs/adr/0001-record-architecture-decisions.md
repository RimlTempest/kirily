# ADR-0001: アーキテクチャ決定を記録する

- 状態: 採用
- 日付: 2026-09-21

## 背景

Kirily は「なぜそうなっているか」が品質に直結する判断を多く含む。
Preview と Export を分ける、画像をサーバーへ送らない、AI をアダプタの裏に置く。
どれもコードを読んだだけでは理由が分からず、半年後の自分が
「こっちのほうが簡単だ」と壊しうる。

## 決定

設計判断は `docs/adr/NNNN-<slug>.md` に記録する。書式は
背景 / 決定 / 結果 / 代替案。**決定を変えるときは新しい ADR を書き、
古いものは「却下」と記して残す**（消さない）。

CI の `guard` ジョブは ADR の不変条件のうち、機械的に検査できるものを
検査する。ADR とジョブは対で追加する。

## 結果

- 判断の理由が追跡できる
- `guard` ジョブが落ちたとき、どの ADR を読めばよいか分かる

## 代替案

- README に書く → 追記されるばかりで、いつの判断か分からなくなる
- 書かない → Kirily の場合、失うものが大きすぎる
