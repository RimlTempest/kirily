# ADR-0021: 縁の調整と、余白を詰める

- 状態: 採用
- 日付: 2026-09-21

## 背景

ADR-0011 で `pale-subject-on-white.png` の輪郭を測ったとき、
残っていた縁の正体はこうだった。

```
x=94  a=13  rgb=255,255,255
x=100 a=44  rgb=255,255,255
```

**色は純白、つまり完全に背景**なのに、マスクが「覆われている」と言っている。
モデルの解像度を引き伸ばしたランプで、色差マッティング（ADR-0013）でも
アルファの問題なので消せない、と記録した。

利用者がここで取る行動は決まっている。**「少し締める」**である。
背景除去ツールにはどれもこの操作があり、Kirily には無かった。

調査でも、求められる機能の筆頭に
edge refinement（feather / smoothing）と auto crop が挙がる。

## 決定 1：締める / ぼかす

どちらも**ぼかし 1 回**から出る。段差をぼかすと `2r+1` 画素のランプになるので、
半分ではない高さで読めば縁が動き、その高さをどれだけ急に写すかで柔らかさが決まる。

```
alpha = clamp((blurred - level) · gain + 0.5)
level = 0.5 - shrink / (2r + 1)
gain  = (2r + 1) / feather
```

### 半径は要件から解いた

最初に書いた `radius = max(|shrink|, feather/2)` では、
**縁から遠い内部まで値が動いた**（255 が 159 になった）。
ランプに移動と柔らかさの両方が収まらず、写像が縁を越えて届いていた。

内部が 1、外部が 0 に飽和する条件を書き下すと
`span >= feather + 2·|shrink|` になる。半径はこれを解いた値にした。
テストが内部の値を見ているので、この種の取りこぼしは残らない。

**符号も一度間違えた。** `level` を上げると縁は被写体側へ寄る。
直感と逆向きなので、テストで固定してある。

### マスクの編集ではなく、マスクの見え方

crop と同じ扱いにした。合成のときに適用するので、
レンダラと書き出しが同じものを見て、undo は関与しない。

### 測った結果

`pale-subject-on-white.png`、高精度段、濃い背景に置いたときの
「アルファは半端なのに画像は純白」な画素の数:

| 締める | 不透明  | 半透明 | **縁**  |
| ------ | ------- | ------ | ------- |
| 0      | 943,421 | 40,492 | **238** |
| −1px   | 928,964 | 28,802 | **38**  |
| −2px   | 922,191 | 30,507 | 52      |

**−1px で縁が 84% 消える。**

−2px は縁が**増える**。締めすぎると内側に新しい半端な帯ができるからで、
「もっと締めれば良い」ではないことが数字に出ている。
既定値を 0 にして利用者に委ねたのはこのためでもある。

## 決定 2：余白を詰める

見えているものを囲む最小の矩形を crop にする。
切り抜いたあとに欲しくなるのはたいていこれで、手でドラッグする理由が無い。

閾値は 1 ではなく **8**。精緻化とマッティングは被写体のはるか外側に
1 桁のアルファを散らすので、1 で詰めると**何も詰まらない**。

見えているものが無いとき、あるいは被写体が四辺に接しているときは
画像全体を返す。空の矩形は、利用者が目で戻れない状態になる。

トリミング道具の縦横比の隣に置いた。これは crop だからである。

## 費用

1254²:

```
adjustEdge  締める -1                12.7ms
adjustEdge  ぼかし 3                 13.7ms
adjustEdge  締める -2 + ぼかし 4     35.5ms
cropToSubject                        10.4ms
```

`adjustEdge` は合成のたびに走るので、ブラシ 1 ストロークごとに乗る。
既定（0/0）では `isNeutral` で素通りするので、**使っていない人は払わない**。

## 途中で整理したもの

`boxBlur` を `guided.ts` から `blur.ts` へ出した。
縁の調整も同じものを必要とし、端の詰め物は**片方だけ間違える種類の細部**である
（実際 ADR-0019 で TS と Rust の両方が間違えていた）。
Rust 側は `kirily-raster::guided` に置いたままで、向こうで要るのはそこだけである。

## 却下した案

**モルフォロジー（収縮・膨張）で締める。** 整数画素でしか動かせず、
0.5px という指定ができない。輪郭のアンチエイリアスを守るのが
この製品の主題なので、そこを整数に落とす理由が無い。

**既定で −1px を入れておく。** この画像では効くが、別の画像では
被写体を削る。測ったのは 1 枚であって、全部ではない。
