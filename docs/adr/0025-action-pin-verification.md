# ADR-0025: ピンが実在し、名乗っているものであることを検査する

- 状態: 採用
- 日付: 2026-09-22

## 背景

`guard` はこう書いていた。

```bash
if grep -nE '^\s*-?\s*uses:\s*[^@]+@(v[0-9.]+|main|master)\s*$' .github/workflows/*.yml; then
  echo "::error::Pin every action to a full commit SHA"
```

**タグが書いてあれば落とす。** それ以外は通す。

ADR-0024 で `cloudflare/wrangler-action` を足したとき、
`# v3` と添えて SHA を書いた。40 桁の 16 進数とタグ名が並んでいて、
正しい pin と見分けがつかない。**通った。**

調べたら、その SHA は実在した（`da0e0df…`、2025-03-15）。
ただし `v3` のものではなかった。記憶から出てきた古い SHA である。

**「SHA が書いてあるか」と「その SHA が正しいか」は別の性質だった。**

## 決定

`tools/check-action-pins.ts` が、ワークフローの `uses:` を 1 つずつ見る。

### パースが落とすもの

|                    | 理由                                                         |
| ------------------ | ------------------------------------------------------------ |
| タグ・ブランチ     | 可動。乗っ取られた action が次の実行から任意コードを走らせる |
| 短縮 SHA           | pin ではない                                                 |
| 末尾コメントが無い | どの版なのか誰にも分からず、照合もできない                   |

`./` で始まるものと `docker://` は見ない。git の ref から取ってこない。

### GitHub に 2 つ訊く

**「このコミットはこのリポジトリにあるか」** — 404 か **422** なら無い。
422 は「リポジトリはあるがそのコミットは無い」で、
でっち上げた SHA はこちらで返ってくる。両方を同じ扱いにする。

**「コメントが名乗っているタグとの関係は」** — `compare/{sha}...{tag}` が答える。

| status      | 判定   | 意味                                          |
| ----------- | ------ | --------------------------------------------- |
| `identical` | 通す   | タグがまだ動いていない                        |
| `behind`    | 通す   | **タグが先へ進んだ。意図した pin の通常の姿** |
| `ahead`     | 落とす | タグより新しい。コメントが実態より古い        |
| `diverged`  | 落とす | 別の系列。**今回の間違いはこれ**              |

`behind` を通すことが要点である。ここを落とすと、
**タグを追いかけさせる圧力になり、pin する意味が消える。**

### 答えが得られないときは通さない

レート制限（403）や障害で判断できないなら落とす。
「訊けなかったので通した」は、検査が無いことと同じである。

トークンは `GITHUB_TOKEN` → `GH_TOKEN` → `gh auth token` の順に探す。
無認証は 1 時間 60 回で、数回の実行で尽きる。そうなると
この検査は**開発者が無視することを覚えるだけの雑音**になる。

## テスト

パースは純粋なので単体で固定した（ローカル action、docker action、
短縮 SHA、コメント無し、行番号、1 ファイルに複数）。

GitHub に訊く部分は `Ask` を注入する。ネットワークを使わずに
6 つの status と 403 を固定できる。

17 件。

## 却下した案

**タグと SHA が完全一致することを要求する。** `behind` が落ちる。
つまりタグが動くたびに pin を追う羽目になり、pin をやめるのと変わらない。

**Dependabot に任せる。** 上げてはくれるが、
**人が手で書いた間違った pin は上げてくれない。** 今回はそれだった。

**`guard` の grep を賢くする。** 正しい SHA かどうかは、
grep が持っていない情報である。訊きに行くしかない。
