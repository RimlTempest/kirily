# ADR-0018: 書き出し形式を選べるようにする

- 状態: 採用
- 日付: 2026-09-21

## 背景

`exportImage` は最初から PNG / WebP / JPEG の 3 つを書ける。
ボタンがあったのは PNG だけだった。

残り 2 つは**書く前に答えが要る**。品質と、JPEG の場合は
透明部分をどうするか。その答えを持つ場所が無かった。

## 決定

### 適用されない選択肢は出さない

PNG の隣に品質スライダーがあれば、それは何もしないつまみである。
WebP の隣に背景色があれば、透明が捨てられようとしていると読めるが、
WebP は透明を保つ。

だから、形式ごとに要るものだけを出す。

| 形式 | 品質 | 透明部分の色 | 透明 |
| ---- | ---- | ------------ | ---- |
| PNG  | —    | —            | 残る |
| WebP | ○    | —            | 残る |
| JPEG | ○    | ○            | 無い |

### 形式を変えても答えは残る

品質を落として JPEG を見に行き、WebP に戻ってきた人は、
それを取り消したつもりではない。`withFormat` は quality と background を保つ。

### ボタンが形式を言う

「⬇️ JPEG で書き出す」。何が書かれるかを読むのに、何も開かなくて済む。

### JPEG を選んだらプレビューの背景もその色にする

これがこの変更でいちばん重要な部分である。

JPEG にアルファは無い。選んだ色が**ファイルに焼き込まれる**。
その間ずっと市松模様を見せていたら、色を見えないまま選ぶことになり、
**プレビューが書き出すものと一致しなくなる**。
Preview / Export を分けた理由（kirily-design.md §16）が崩れる。

キャンバスの画素は透明のままで、後ろの要素の背景色を変えるだけなので、
レンダラには何の変更も要らない。

## テスト

`export.spec.ts` が 3 形式それぞれについて、**実際に書かれたバイト**を見る。

- PNG … `89504e47`、角のアルファ < 32
- WebP … `52494646` … `57454250`、角のアルファ < 32
- JPEG … `ffd8ff`、角のアルファ = 255 で、角が黒く中心が明るい
- 品質 … 100% のファイルが 20% のファイルより**大きい**
- 適用されない選択肢が出ていないこと

最初は品質のテストが「どちらも JPEG である」ことしか見ていなかった。
テスト名が主張していることを検証していなかったので、バイト数の比較を足した。

`export-settings.ts` 側は 14 件の単体テストで、
どの形式が何を要るかと、設定の持ち回りを固定している。

## 却下した案

**ボタンからドロップダウンで選ばせる。** 選択肢は 3 つしかなく、
そのうち 2 つは追加の設定を連れてくる。開いて閉じる操作を挟むより、
そのまま並べたほうが短い。

**形式ごとに品質の既定値を変える。** WebP は同じ品質値でも
JPEG より小さくなる、という話は本当だが、
数字の意味が形式ごとに変わるほうが分かりにくい。
